# R6 checkpoint: Safe HTTP real observation

## 阶段

R6.1 Safe HTTP（R6 第一增量）。

## 目标

真实低影响 HTTP 观察：GET/HEAD 限定、手动重定向逐跳授权、私网/回连拒绝、
摘要化存储（body 不落盘）、200/404/403/429/超时/TLS 分别建模，架构门控
阻止 CDN/第三方/共享云探测并生成 review item。

## 已完成

- **真实客户端**（`safe_http_client.py`，`SafeHttpFetchClient`）：
  - `http.client` 手动单跳（不自动跟随重定向），每跳重新授权：host 必须在
    `allowed_hosts`（确认范围），连接前 DNS 预解析拒绝私网/回连/链路本地/
    保留/组播地址（连接前阻断，零流量触达）。
  - 重定向链手动跟随（上限 5），越界 Location → `redirect_blocked`，链上
    已达跳数照实记录；第三方从未被联系。
  - 响应头白名单（server/content-type/content-length/location/etag/via 等，
    Cookie/Auth 类永不落盘）；body 读取上限 256KB 后仅存 SHA-256 摘要 +
    字节数 + truncated 标志；https 对端证书 DER→SHA-256（tls_sha256）。
  - 状态建模：observed/timeout/tls_error/http_error/redirect_blocked/
    private_blocked + `response_class`（ok/not_found/forbidden/rate_limited/
    other——200/404/403/429 分别建模）。
  - fetch_hop 与 resolver 可注入（测试零网络）；UA 标识
    `surface-intel/0.1.0`；方法白名单 GET/HEAD。
- **适配器**（`adapters/safe_http.py` 扩展）：富结果字段映射（final_url/
  headers/body_sha256/body_truncated/tls_sha256/response_class 等）、
  transport_status 非 observed → timed_out/failed（观察仍落盘留审计）、
  方法策略按 context `allowed_methods`（默认 GET，runner 开启 HEAD）、
  RDAP 同款锚点模式：scope 检查目标为 in-scope host，完整 URL 走
  `lookup_target`，观察 `target`=URL、`scope_anchor`=host。
- **Runner**（`safe_http_runner.py`）：门控顺序 = scope confirmed →
  active authorization（active_testing_allowed + 级别 ≥ safe_discovery）→
  host in scope → R4 架构门控。架构命中阻断集（third_party + cdn/waf/lb/
  cloud_hosting 的 candidate/likely）→ 高优先级 review item（gap 行，
  幂等）+ blocked，零流量。重定向链 scope 分类：全在范围内 candidate、
  任一越界 needs_review。统一证据（redact+digest evidence + observation）。
- **CLI**：`http-observe <task-id> --url <url> [--method GET|HEAD] --real
  --confirm-real`，任务置 `probing_authorized`，结果
  completed/failed/blocked 收口。

## 已知限制

- 非 http.client 传输行为差异（如 HTTP/2、压缩）：当前仅 HTTP/1.1 明文
  观测语义；gzip body 摘要按传输字节计。
- DNS 预解析与实际连接解析存在 TOCTOU 窗口（DNS rebinding 理论残留）；
  连接级私网二次校验可在 R7 收口。
- 重定向链上限 5（超限 http_error:too_many_redirects）。
- 未实现 HEAD 的语义差异建模（当前 HEAD 与 GET 同路）。
