# R3 checkpoint: CT passive adapter first increment

## 阶段

R3.2 CT Adapter（R3 被动多源闭环第二增量）。

## 目标

以统一 Adapter 形式接入被动证书透明度日志查询（crt.sh 或等价源），保存证书
CN、SAN、issuer、serial、validity、log source、first_seen/last_seen；SAN 只产生
候选关系，不单独确认归属，第三方和范围外域名进入 candidate/needs_review。

## 已完成

- `CertificateTransparencyAdapter`（`adapters/ct.py`）：注入式 CT log client
  （manifest `ct_log` 1.0，`passive_only`，cost_units=1）。observed/empty 是定案
  结果（动作 `completed`）；rate_limited/http_error/timeout 属基础设施失败
  （`failed`/`timed_out`）；未知 client 状态拒绝为
  `invalid_client_status:*`；transport 异常粗分类 `ct:<ExcName>`。
  每次查询规范化为一条 observation（`certificates` 行数组 +
  `matched_count`），证书行字段固定为 `common_name`、`sans`、`issuer`、
  `serial`、`not_before`、`not_after`、`first_seen`、`last_seen`、`log_id`、
  `log_source`。
- 真实 client（`ct_client.py`）：`CrtShClient` 走 crt.sh JSON API
  （`https://crt.sh/?q=<domain>&output=json`），fetch 经 `asyncio.to_thread` 注入
  （测试零网络）；查询参数 percent-encoded 防参数注入；HTTP 429→`rate_limited`、
  其他 HTTP 错误→`http_error`、超时→`timeout`、坏 JSON/非列表→`invalid_response`；
  `name_value` 按行拆分为 SAN（小写、去尾点、保序、CN 去重插入）；通配符 SAN
  保留 `*.` 原样，由 runner 分类；原始响应体不落盘、不进日志。
  `SURFACE_INTEL_CT_ENDPOINT` 可覆盖端点；health 只报告配置，不发起网络请求。
- `run_ct_search`（`ct_runner.py`）：runner 级 `scope.confirmed` + `is_in_scope`
  门控在任何 client 调用之前；单动作经 `AdapterExecutor`（`adapter_call` 审计 +
  `ct_log` 预算事务性 reserve/commit + capability 检查）。观察经 `redact` 后落盘
  evidence/observation，带 `scope_version`、`observed_at`、
  `source_quality=direct`、`license_status=public_ct_log` 和
  `related_scope_status`。分类规则：全部名称在授权范围内 → `candidate`（CT 匹配
  单独绝不确认归属）；任何第三方/范围外名称（CN 或 SAN）→ `needs_review`；
  无证书 → `not_applicable`。通配符 SAN 按去掉 `*.` 的基础域判定。绝不创建
  asset 行，绝不产生 `confirmed`/`confirmed_direct` 关系。
- CLI：`ct-health --real`（只报告端点配置）、
  `ct-search --real --confirm-real`（要求已确认任务 + 域名在范围内，任务进入
  `collecting_passive`，按 completed/failed/blocked 收口），与 FOFA/DNS 同级
  显式门控。

## 已知限制

- crt.sh 无分页/游标：大域名可能返回大量证书行甚至超时；单动作预算不约束
  observation 体积。速率/并发/缓存统一治理属 R3.4/R5。
- crt.sh `q=` 为身份包含匹配，可能返回名称包含该串的其他域名证书——这正是
  `needs_review` 分类存在的原因，但候选噪声需 R4 归并层过滤。
- `first_seen`/`last_seen` 当前都是 crt.sh `entry_timestamp`（该行首次入库
  时间）；跨行聚合出真实首末观察属 R4。
- 未去重重新签发的证书（同 SAN 不同 serial/log id 各存一行）；归并在 R4。
- CT 观察尚未进入报告工作表，也未接入 `run_offline_task` 的被动计划循环
  （R3.4/R7 统一）。

## 是否可恢复

是。CT 动作审计在 `adapter_call`；观察/证据落盘于 `evidence`/`observation`；
无长事务或内存态。重复 `ct-search` 是合法重新观察（新 observed_at），预算消耗
按 DB budget 表记账，不伪造回退。
