# R3 checkpoint: DNS passive adapter first increment

## 阶段

R3.1 DNS Adapter（R3 被动多源闭环第一增量）。

## 目标

以统一 Adapter 形式接入被动 DNS 解析，只处理授权 scope 根下的目标，不递归
扩大到未授权域名，结果写入 observation/evidence 并记录 source quality、
许可状态和时间；真实 DNS 请求受 scope、预算和超时门控。

## 已完成

- `DnsAdapter`（`adapters/dns.py`）：注入式 resolver client；记录类型白名单
  A/AAAA/CNAME/NS/MX/TXT/SOA（AXFR/ANY 在 validate 被拒绝）；NXDOMAIN/empty
  是定案否定观察，servfail/refused/rate_limited/timeout 是基础设施失败；
  DNSSEC 只记录上游 AD 位，不做本地验证。
- 真实 client（`dns_client.py`）：dnspython 异步 resolver，绝对名称查询跳过
  search 列表，per-query timeout/lifetime，EDNS0；异常映射为结构化状态；
  `SURFACE_INTEL_DNS_NAMESERVERS` 环境变量可覆盖 nameserver。
- `run_dns_lookup`（`dns_runner.py`）：runner 级 scope.confirmed +
  is_in_scope 门控（任何 client 调用之前）；每个记录类型是独立动作，经
  `AdapterExecutor` 执行（`adapter_call` 审计、capability 检查、
  `dns_resolver` 预算事务性 reserve/commit）；单类型失败隔离，聚合为
  completed/partial/failed；解析值（A/AAAA/CNAME/NS/MX/SOA）只有自身在授权
  ips/cidrs/domains 内才是 `confirmed`，否则 `candidate`；TXT 不评估；
  绝不递归解析 CNAME 或第三方目标。
- CLI：`dns-health --real`（只报告 resolver 配置）、
  `dns-lookup --real --confirm-real`（要求已确认任务 + 域名在范围内，任务进入
  `collecting_passive`）。
- `Scope.to_dict()` 用于 ExecutionContext 的 scope payload 往返。

## 已知限制

- 统一速率/并发限制和缓存仍属 R3.4/R5；当前仅 per-query timeout 与任务级
  `dns_resolver` 预算约束总查询数。
- `NoNameservers` 统一映射为 `servfail`，未区分 REFUSED/限流 rcode 细节。
- DNSSEC 只记录 AD 位（True/None），不做本地链验证；未置位时无法区分
  “验证失败”与“resolver 未验证”。
- DNS 观察尚未进入报告工作表（R3.4/R7 统一多源报告），也未接入
  `run_offline_task` 的被动计划循环。
- MX 记录格式为 `"<pref> <exchange>"` 字符串；SOA 为
  `"<mname> <rname> <serial>"`；R4 归并层需按此约定解析。

## 是否可恢复

是。每个 DNS 动作的审计行在 `adapter_call`；观察/证据落盘于
`evidence`/`observation`；无长事务或内存态。重复 `dns-lookup` 是合法重新观察
（新 observed_at/TTL），预算消耗按 DB budget 表记账，不伪造回退。
