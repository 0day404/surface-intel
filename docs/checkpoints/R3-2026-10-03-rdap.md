# R3 checkpoint: RDAP/WHOIS passive adapter first increment

## 阶段

R3.3 RDAP/WHOIS Adapter（R3 被动多源闭环第三增量）。

## 目标

以统一 Adapter 形式接入被动注册数据查询，保存注册组织、网络、ASN、CIDR、
abuse 联系信息和查询时间；WHOIS fallback 明确数据质量和许可状态；不能因为
组织名或 ASN 相同就确认资产归属。

## 已完成

- `RdapAdapter`（`adapters/rdap.py`）：注入式 lookup client（manifest
  `rdap_lookup` 1.0，`passive_only`，cost_units=1）；目标种类白名单
  `TARGET_KINDS = domain/ip/asn`，validate 拒绝空目标与未知种类。
  observed/not_found 是定案结果（动作 `completed`）；
  rate_limited/http_error/unsupported/invalid_response 是基础设施失败
  （`failed`），timeout 是 `timed_out`；未知 client 状态拒绝。观察规范化为
  `target`+`target_kind`+`record` 结构，`record` 字段固定（handle/name/
  country/organizations/registrar/abuse_contacts/events/cidrs/ip_version/
  start_address/end_address/asn_start/asn_end/statuses/nameservers）。
- 真实 client（`rdap_client.py`）：`SequentialLookupClient` = `RdapOrgClient`
  优先 + `WhoisFallbackClient` 回退。RDAP 走 rdap.org bootstrap
  （`https://rdap.org/{domain|ip|autnum}/<target>`，`SURFACE_INTEL_RDAP_ENDPOINT`
  可覆盖），fetch 经 `asyncio.to_thread` 注入（测试零网络）；URL 参数
  percent-encoded；404→not_found（RIR 覆盖完整，ip/asn 的 404 是定案否定）、
  429→rate_limited、其他 HTTP 错误→http_error、坏 JSON→invalid_response。
  RDAP JSON 规范化只保留结构化字段（vCard fn/email、events、cidr0_cidrs、
  status、nameservers），丢弃 remarks 等自由文本。域名 404 且 WHOIS 确认已
  注册时回退 WHOIS：端口 43 socket、IANA 首查、至多一次 referral、只提取
  白名单字段（domain name/registrar/registrant org/creation/expiry/name
  server），绝不挖掘联系人地址，原始文本不落盘不进日志；回退记录强制携带
  `data_quality=whois_fallback`。WHOIS 确认未注册时保留 RDAP 404 定案。
- `run_rdap_lookup`（`rdap_runner.py`）：runner 级门控在任何 client 调用之前
  ——scope.confirmed、target 在范围内（domain 按域名规则；ip 需在授权 IP
  列表或授权 CIDR 内）、**ASN 直查被 `asn_scope_binding_deferred` 拒绝**
  （scope 文件不授权 ASN，绑定依据属 R4 归并层）。单动作经
  `AdapterExecutor`（`adapter_call` 审计 + `rdap_lookup` 预算事务性
  reserve/commit）。观察带 `scope_version`、`observed_at`、`source_quality`
  （direct/whois_fallback）、`license_status`（public_rdap/
  whois_text_unverified）和 `related_scope_status`：not_found →
  `not_applicable`，其余一律 `candidate`——注册数据只能产生候选归属关系，
  组织名或 ASN 相同绝不确认资产；RDAP 记录中更宽的 CIDR 不是范围扩大
  （相邻 IP 仍被拒）。绝不创建 asset 行。
- CLI：`rdap-health --real`（只报告端点配置）、
  `rdap-lookup --real --confirm-real --kind domain|ip|asn`（要求已确认任务 +
  目标在范围内，任务进入 `collecting_passive`）。

## 已知限制

- ASN 直查暂被 runner 拒绝（`asn_scope_binding_deferred`）：scope 文档不能
  授权 ASN，需要 R4 归并层提供"ASN 与授权目标的关系"绑定依据后放开；适配器
  与 client 的 autnum 路径已实现并由 fixture 覆盖。
- WHOIS fallback 只在域名 RDAP 404 后触发一次；未实现 registrar WHOIS 深挖
  （ referrals 之后的二次跳转）、未解析非英文字段名。
- RDAP bootstrap 固定 rdap.org 单跳重定向，未内置 IANA bootstrap 文件缓存；
  rate limit 治理属 R3.4/R5。
- `abuse_contacts` 仅取 RDAP abuse 角色 vCard email；WHOIS 文本永不挖掘
  联系人地址（脱敏策略优先于覆盖面）。
- RDAP/WHOIS 观察尚未进入报告工作表，未接入 `run_offline_task` 被动计划
  循环（R3.4/R7 统一）。
